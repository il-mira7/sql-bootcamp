# 10. Isolation Levels

Десятый проект — транзакции и уровни изоляции PostgreSQL. Каждый сценарий исполняется в **двух параллельных сессиях psql**: воспроизводятся классические аномалии конкурентного доступа (потерянное обновление, неповторяющееся чтение, фантомное чтение, взаимоблокировка) и показывается, как меняется поведение на уровнях `REPEATABLE READ` и `SERIALIZABLE`.

## Упражнения

| Файл | Что демонстрирует |
|------|-------------------|
| `day08_ex00.sql` | базовая транзакция: `UPDATE` в первой сессии виден второй только после `COMMIT` |
| `day08_ex01.sql` | lost update на уровне `READ COMMITTED`: вторая сессия молча перезаписывает изменения первой |
| `day08_ex02.sql` | тот же сценарий на `REPEATABLE READ`: вторая сессия получает ошибку сериализации вместо перезаписи |
| `day08_ex03.sql` | non-repeatable reads на `READ COMMITTED`: два одинаковых `SELECT` в одной транзакции дают разные результаты |
| `day08_ex04.sql` | тот же сценарий на `SERIALIZABLE` |
| `day08_ex05.sql` | phantom reads: `INSERT` в параллельной транзакции меняет результат агрегата (`SUM`) |
| `day08_ex06.sql` | фантомное чтение на `REPEATABLE READ` — снимок данных изолирован от чужих вставок |
| `day08_ex07.sql` | deadlock: две транзакции блокируют одни строки в разном порядке |

## Запуск

Файлы читаются как сценарии для двух терминалов: блок «Session #1» исполняется в одном psql, «Session #2» — во втором, параллельно:

```bash
psql -d pizza -f materials/model.sql
# терминал 1
psql -d pizza
# терминал 2
psql -d pizza
```
