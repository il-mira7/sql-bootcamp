# 11. Functions and Procedures

Одиннадцатый проект: хранимые функции и триггеры. Строится таблица аудита, в которую триггеры пишут все изменения строки (вставка, обновление, удаление), затем один универсальный триггер через `TG_OP`; дальше — собственные функции на SQL и PL/pgSQL: с параметрами по умолчанию, возвратом `SETOF`/`TABLE`, вариативными аргументами и рекурсией.

## Упражнения

| Файл | Что делает |
|------|------------|
| `day09_ex00.sql` | таблица аудита + триггер `AFTER INSERT` на людей |
| `day09_ex01.sql` | триггер `AFTER UPDATE`: в аудит пишется старое состояние строки (`OLD`) с меткой `U` |
| `day09_ex02.sql` | триггер `AFTER DELETE` с меткой `D` |
| `day09_ex03.sql` | единый триггер на `INSERT OR UPDATE OR DELETE` с ветвлением по `TG_OP` |
| `day09_ex04.sql` | функции на SQL с возвратом `SETOF person`: женщины и мужчины |
| `day09_ex05.sql` | одна функция с параметром по умолчанию вместо двух отдельных |
| `day09_ex06.sql` | функция на PL/pgSQL с `RETURNS TABLE` и тремя параметрами (человек, цена, дата) |
| `day09_ex07.sql` | функция с `VARIADIC`-аргументом: минимум из переданного списка чисел через `unnest` |
| `day09_ex08.sql` | числа Фибоначчи: рекурсивный CTE внутри функции с параметром-пределом |

## Запуск

```bash
psql -d pizza -f materials/model.sql
psql -d pizza -f src/ex00/day09_ex00.sql
```

Упражнения создают объекты и меняют данные, выполняются по порядку; закомментированные `SELECT` в конце файлов показывают, как проверить результат.
